## Proposed title

Surface rendering: separate components, reject incomplete crops and recover Zarr outputs

## Contribution narrative

This bundle contains three small changes to the existing Volume Cartographer workflow, with patches, reproducible checks, measurements and limits. The work was prepared using AI agents, and an agent other than each implementer independently checked the supporting results. We do not claim human review or external adoption.

**Separate disconnected pieces before rasterization.** An optional, default-off `--pack-components` flag for flatboi places disconnected surface components in separate horizontal intervals after the existing SLIM calculation. Source XYZ, faces and solver settings are unchanged. This prevents different components from overlapping in the output raster or being joined by adjacent output grid samples.

On two full-resolution public PHerc0814 meshes, using five SLIM iterations, cross-component raster rejections fell from 189 and 399 to zero. Output grid edges joining different components fell from 106 and 284 to zero. The output becomes wider, and within-component problems remain: one and 356 observed within-component rejection pairs were not removed.

A local real-CT comparison followed an edge selected from geometry before examining the scan. Its endpoints were approximately 304 scan voxels apart. Before packing, 1,280 pixels interpolated between the components; after packing, the corresponding faces were tracked in two crops with zero mixed pixels. The crops differ in valid area and raster phase and are not pixelwise aligned in 3D. A separate agent checked all 39,760 valid samples and 15 TIFFs. The second component's correspondence to one correct papyrus sheet remains unresolved; ink readability and fiber preservation are not established.

The published follow-up adds `--pack-components-preserve-grid`, which translates components by whole cells after the original fixed-point snapping. On the same two inputs, it retains all 40,944 and 254,263 original sample owners and XYZ bits, recovers 189 and 399 distinct hidden samples, and eliminates cross-component conflicts. All output interpolation weights match the original lattice. A separate agent independently enumerated every triangle and ran the second input without observation code; both product outputs match their observed XYZ TIFFs. This strengthens the same component-packing contribution.

In one preselected 64 × 64 real-CT ROI, all 14,080 samples supported by a single component retained their positions, signed normals, float CT values and uint8 pixels across five layers (two components × 1,408 samples × five layers, using the tested linear surface path). The original 1,280 mixed-support pixels became invalid in each separated ROI, rather than representing reconstructed paper. A real single-component PHerc0139 w035 control also retained all three XYZ files, scale and SLIM energy with the option enabled at keep100 and five iterations; only the generated UUID differed.

On the first surface at keep1.5 with 103 invalid UV vertices, a further local check retains all 21,350 original sample owners and recovers 1,671 distinct cells. It removes 1,848 cross-component rejections; 177 previously hidden same-component conflicts become visible, while all 11,340 original same-component rejections remain represented. [Low-keep result and scope](component-packing-grid-preservation/LOW_KEEP_RESULT.md). Other CT windows, sampling modes, readability and broader inputs remain untested. [Local CT result](component-packing-grid-preservation/CT_RESULT.md).

A further standard CMake build on the saved 7ad02f4 baseline rebuilt the shared vc_core and both direct callers from the same changed header. The first surface retained all XYZ file hashes and float32 bits, with the same nominal scale. A subsequent combined build on fixed upstream revision 14d4e725 also passed with all three contributions applied: the R005 first-surface outputs remained identical, the R007 18-case CLI check passed, and the R009 normal/fresh-resume/L0-only-resume outputs matched across all 15 files and six logical levels. The lead independently checked all 2,269 source files and the saved outputs. [Combined build and scope](integrated-build/README.md). Replacing a shared library under old callers remains untested. [Standard build result](component-packing-grid-preservation/STANDARD_BUILD_RESULT.md). [Local supplement and scope](component-packing-grid-preservation/README.md). These results are included in the published follow-up supplement linked below.

**Reject an incomplete manual crop before reading inputs.** The existing `vc_render_tifxyz` CLI silently uses the full canvas when a manual width or height is omitted or nonpositive. On the saved PHerc0814 surface, omitting the height from an intended 128 × 128 crop selected 13,600 × 3,440 instead: 46,784,000 selected pixels per layer rather than 16,384. An observation build stopped at crop selection, without rendering the full canvas.

The patch rejects such incomplete crop requests before opening the volume or surface. It preserves intentional full-canvas rendering, valid origin defaults and clipping, automatic cropping, help and TIFF-part merging. Independent verification passed 18 real-CLI checks. Six valid crop selections matched the original, and three normal-render TIFF layers matched their original controls byte for byte. A data-free regression script is included. We have not measured full-render time, transfer or monetary savings, and have not established an external incident caused by this mistake.

**Recover incomplete Zarr output and describe the levels actually written.** The original renderer could finish level 0 and then fail because level 1 had no array metadata, both on a new output path with `--resume` and on a level-0-only partial output. The change initializes missing pyramid arrays from level 0's saved format while retaining existing array metadata. Six prepared partial states from a fixed PHerc0814 128 × 128, 101-layer real-CT output matched all 14 files of the original normal control after resume. A separate-agent replay retained existing level-0 files and metadata in a prepared mixture of gzip, raw and Blosc arrays, and completed the missing levels. Root OME attributes and lower-level pixels are recomputed by the existing code; full avoidance of recomputation is not claimed.

The same item corrects OME datasets when `--pyramid false`: normal and metadata-only `--pre` output now list only array 0. The combined crop/resume/OME renderer preserved the normal and first-use resume controls and passed the crop CLI checks. A real Python wrapper and nanobind extension exposed the existing-level preservation mode; a tiny-array check and independent replay verified the boundary. Subsequent local research163 rebuilt the standard `_catalog` and `_reader` targets on fixed revision 14d4e725 and passed the same check through both real package initializers. The lead independently checked seven retained files and all 80 gzip/raw values. A wheel and the full pytest runner remain untested; this later evidence is not included in the frozen public supplement. These small synthetic checks supplement the real-CT evidence.

Local R245 checked the reader impact on the saved PHerc0814 128 × 128 × 101 output. A copy differing only in the old OME dataset list fails in the standard OME-Zarr Python 0.21.0 Reader with `ArrayNotFoundError` at absent level 1; the corrected list returns one image array with identical level-0 pixels. Villa's `vc_reader` 0.1.0 also fails when selecting its documented coarsest level from the old list and succeeds with the corrected list. Direct level-0 reads succeed in both. The lead independently reproduced the OME contrast. The original old fixture also lacks a root group marker, so that separate failure was excluded from the metadata effect. Version-detection logging remains in both cases. These are fixed reader tests on saved combined-build outputs, not a standalone current-main build, GUI test, or human-use report. [Reader evidence](../../../research/245-r123-reader-impact.md) · [Input-provenance correction](../../../runtime/r245-provenance-correction.json).

Local R246 then built the unmodified fixed upstream and applied only R123, with unchanged shared dependencies. Both executables rendered the same real PHerc0139 w035 crop, 64 × 64 pixels over 28 layers. The generated outputs differed only in `.zattrs`; all 114,688 level-0 pixels were identical. OME-Zarr Python 0.21.0 failed at absent level 1 for the original output and read the complete corrected image. Default-pyramid output was byte-identical across 14 files, and `--pre --pyramid false` advertised only level 0. The lead independently checked all native output files and raw pixels. This establishes the standalone fix on that pinned revision, without claiming GUI or human verification. [Standalone reproduction and build records](../../../experiments/vesuvius/r009/20261116-standalone-metadata01/README.md).

An additional check, prepared locally after the initial public snapshot, uses a second scroll, PHerc0139 w035, at 64 × 64 × 28. The product renderer was stopped at two function entries: after level-0 pixels were saved, and after only level-0 array metadata existed. Resuming copies of the outputs left by those processes matched the normal run's 14 files and all six resolutions. The existing eight and two files respectively retained their contents, modification times and inodes within each resumed copy. The old renderer failed at missing level 1 from the latter state. A separate lead replay reproduced all three outcomes. The debugger failed to record the product's terminating OS signal, so this establishes recovery from those observed stopped-process outputs, not verified SIGKILL status or general crash tolerance. Mid-chunk corruption, power loss, simultaneous multi-part use, Zarr v3, all codecs/dtypes, downstream GUI viewer behavior and external use remain untested. [Local experiment](../../../research/131-r009-interrupted-render.md) · [Independent verification](../../../research/132-r009-interrupted-verification.md). A further 1 × 129 × 28 real-CT control stopped after the first of two L0 chunks had been saved. Resume preserved all eight existing files, created the second chunk and matched the normal control's 15 files and all six logical levels. The lead independently decoded the raw Zarr chunks and checked the saved file identities. Lower-level array metadata already existed at this stop, so this confirms retention and completion across two chunks, not a new repair-specific rescue. [Interrupted-output scope](zarr-resume-interruption/README.md). These results are summarized in the published follow-up supplement linked below.

These changes reuse the established renderer and public inputs. No paid cloud computation was used for these experiments. Newly authored additions and original explanatory material are offered under MIT; modified upstream Volume Cartographer retains GPLv3, modified upstream vc_reader retains MIT, and dataset-derived material retains the source dataset terms. The tests and diagnostic patches support these product changes rather than forming a separate evaluation-tool submission.
