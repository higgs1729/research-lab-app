# R005：局所配置の実現例と、厳密固定SCAF後の描画比較

2026-11-12 JST。前回SCAFの固定値復元で残った3反転は、固定点を変えず、隣の可動点2個を補正すると解消できた。局所929面の内部重複も0になった。従って、少なくともこの局所入力について「固定条件を両立できない」という説明は当てはまらない。[局所補正](../experiments/vesuvius/r005/20261112-local-kernel01/diagnosis01/result.json)

補正直後は極端な薄面があった。既存SCAFの厳密固定機能で50反復すると歪みを下げつつ非重複を保てた。この結果を試作Fとして既存Dの領域90だけへ入れ、同じ実描画条件で比較した。変更面に関係する拒否74件は全て消え、全体の同一成分への最近傍距離が20 voxelを超える原格子セルは312→281に減った。一方で11セルが新たに20 voxelを超え、歪みもDより大きい。Fは次の研究用候補として保存し、製品・投稿・応募には採用していない。

## 2点を動かす局所診断

入力は[前回run03](61-r005-scaf-trial.md)の固定120点をCへ戻した602点・929面。そのうち変更可能なのは482点で、粗点13点を含む120点は動かさない。

負面を最も多く覆う可動頂点を順に選び、同数なら元頂点IDの小さい方とした。選ばれたのは95387と123536で、それぞれのincident面は6枚、二つの面集合は互いに素だった。一方を動かすと他方の制約が変わる問題はこの入力ではない。

他の頂点を固定すると、三角形の符号付き面積は一つの可動頂点の座標について線形になる。全incident面について、向かいの辺からの符号付き高度を0.01 UV以上にする半平面制約を作った。既存SciPy `linprog` / HiGHSでL∞移動量を最小にする問題を各点に一度解いた。高度0.01は今回の診断条件であり、製品の品質基準ではない。係数探索や新しい最適化器の実装は行っていない。

| 頂点 | 元格子の行・列 | UV移動量（x, y） | L∞移動量 |
| --- | --- | --- | ---: |
| 95387 | 113, 1368 | +0.110457, +0.365890 | 0.365890 |
| 123536 | 127, 1367 | −0.052663, −0.052663 | 0.052663 |

残り600点は開始値と同一。固定値の保持と正の面積を確認したうえで、全929面の内部重複を測ると23→0組になった。float32化後も反転0・縮退0・内部重複0。最小符号付き面積は約0.131512 UV²である。この局所的な実現例をEと呼ぶ。保存後の頂点95387について、面181331の実際の高度は約0.009999999999593893 UVで、指定0.01を約4.06×10⁻¹³下回る。制約を浮動丸め精度内で満たす正向きの実現例であり、高度0.01を厳密に保証した結果ではない。LPの大域最適性や他の入力での成功も証明していない。

## 周囲との交差と、薄面の緩和

Dの配置前UVの当該領域だけをEへ置換すると、変わるのは482点と、それに接する928面だった。全固定183,893点・粗点3,954点はCと厳密に一致し、全478,224面は正面積だった。

変更928面を、同じ細成分1の全375,552面と比較した。内部重複はDで590組、Eで0組。Dの590組のうち、局所929面の中が265組、局所外の面との組が325組だった。異なる細成分は配置前の座標原点が独立のため、この検査では比較していない。変更していない面同士の重複も再集計していない。[全周囲との比較](../experiments/vesuvius/r005/20261112-local-kernel01/global01/result.json)

Eの局所平均歪みは極端に悪い。そこでEを実現可能な初期値とし、既存 `SCAFData.fixed_ids` に固定120点を渡して50反復した。surfaceとscaffoldの既存線形系が固定変数を除去する経路を使う。soft constraintは空にした。この実装のsoft項は元の変数番号へ加算するため、固定変数を除いた系と混在させない。

変更は研究用harnessでの `fixed_ids` 設定、soft mapのクリア、初期値と全反復での固定値完全一致の検査だけ。前回の候補energy修正版headerを再利用したが、この試験ではsoft項自体が空である。元のSCAFソース・既存binary・共有ライブラリを変更せず、Triangle objectと既存コンパイル条件を再利用した。[harness差分](../experiments/vesuvius/r005/20261112-local-kernel01/hard-harness.patch)・[ビルド条件](../experiments/vesuvius/r005/20261112-local-kernel01/build01/state.json)

この50反復後をFと呼ぶ。全反復で固定120点の誤差0とmaterial/scaffoldの正面積を検査し、最終UVで独立した幾何計測を行った。Fも全固定点・粗点を保ち、全478,224面は正面積で、変更928面と同じ成分の全周囲との内部重複は0だった。prepack-float32でも同じ結果である。[Fの比較](../experiments/vesuvius/r005/20261112-local-kernel01/global02/result.json)

| 配置 | 変更面が関与する内部重複 | 局所929面の平均正規化対称Dirichlet | 局所の最大対称伸縮率 |
| --- | ---: | ---: | ---: |
| D：前回のSLIM試作 | 590 | 1.203814 | 4.0723 |
| E：2点補正直後 | 0 | 4434.714273 | 2349.8907 |
| F：Eから厳密固定SCAF 50反復 | 0 | 22.916526 | 113.5344 |

平均は3D面積による重み付きで、等長写像の値は1。最大対称伸縮率は `max(σ, 1/σ)`。FはEより改善したが、重複を許していたDとの比較では強い圧縮が残る。SCAFのmaterial energyは40反復目91.691667、50反復目91.666085とまだ変わっている。50反復で収束したとは言わない。局所最適解や最良の歪みを得たという主張でもない。

## 同じ格子での実描画

凍結済みCの成分配置関数と既存 `flatboi-r005-overridetrace01` を使った。D/Fは同じ入力、keep 1.5、既定50反復、affine fallbackと小成分回復有効、UV overrideを使用。nativeに渡った全UVと用意した配列の一致を確認した。

今回はD/Fで配置後も変更482点以外は完全に同一だった。格子は245×3043、UV範囲は両方 `[0,0]` から `[60838.79296875,4871.38720703125]`。実際のUV格子間隔もx約19.999603、y約19.964702で一致する。前回C/D比較にあった格子間隔の違いは、このD/F比較にはない。[描画条件と変化範囲](../experiments/vesuvius/r005/20261112-local-kernel01/raster-scope01/result.json)

| 指標 | D | F |
| --- | ---: | ---: |
| 出力表面点 | 247,511 | 247,525 |
| 描画時の重複拒否イベント | 638 | 564 |
| うち変更928面が関与 | 74 | 0 |
| 原quad中心から同じ細成分の出力点まで20 voxel超 | 312 | 281 |
| 同40 voxel超 | 78 | 65 |
| 全478,224面の平均正規化対称Dirichlet | 1.173747 | 1.217271 |

拒否イベントの集合差は削除74・追加0で、削除は全て今回変更した面に関係する。残り564イベントの内容は変わらない。出力格子では有効点18個が加わり4個が失われ、所有面が変わった画素は161個だった。

距離は入力の全239,112個の有効quadの3D中心で測った、同じ連結成分の出力点への最近傍距離である。20 voxel以下へ改善したのは42セル、新たに20 voxelを超えたのは11セル。変更面を一枚でも含む467セルに絞ると、20 voxel超は27→18、40 voxel超は10→0。11個の悪化は全てこの467セルの中で、元格子112〜113行・1369〜1374列に集まる。対象外セルは20 voxel超285→263で、新規悪化はなかった。

これは被覆と衝突の数値比較であり、CTや文字の読みやすさを測ったものではない。拒否564件は全体に残り、全メッシュの内部重複が消えたわけでもない。具体的に、前回の面159157・188235は今回変更した928面の外にあり、配置後UVがDと同一で、Fにも内部重複が残ることを独立した整数SATで確認した。Dからの改善をCとの直接比較に読み替えない。[描画評価](../experiments/vesuvius/r005/20261112-local-kernel01/raster01/result.json)

## 再利用物と次の投入

残したものは、固定復元後に一頂点ずつの半平面から実現例を探す小さな診断、既存SCAFの厳密固定を使うharness、変更面対全周囲の評価、同じ格子で描画拒否・被覆・歪みを比較する記録である。一件の局所実験を汎用修復器として統合していない。

ビルド32.91秒、厳密固定SCAF 8.14秒、native描画15.62秒。ビルドの最大子RSSは約1.50 GB、SCAFは約128 MB。CPU1個・1スレッド、native各コマンド300秒・AS 4 GiB、Python各処理300秒・RSS 4 GiB監視で逐次実行した。新規有料計算・GPU・入力取得・依存導入は0。LLM使用とローカル電力は金額換算していない。QuickBuild/O0・共有ホストの実測なので性能比較には使わない。未使用の旧mainを取り込む戻り値警告とSLIM_CACHED再定義警告は前回と同じで、ビルドは成功している。

再実行の入口は `experiments/vesuvius/r005/run_python_bounded.py`。`--script .../20261112-local-kernel01/check_kernels.py --out <新規出力先>` で局所診断を再現できる。nativeはWSL Ubuntuで `native_job_hard.py run --input .../hard-input01/input.json --out <新規出力先>`。使用binary・入力・sourceのハッシュは各stateと後述の凍結manifestに残す。既存出力先へ上書きしない。

Fを研究用候補として保持し、Cの基準とDの比較対照を残す。次の問いは、粗点を保つ契約の下で、細点の固定範囲や対象領域を見直すとこの11セルの欠落と強い圧縮を緩和できるか。今回は反復数を増やす探索や他パッチへの横展開を行わない。領域129など元メッシュの境界分岐への対応も未解決である。

主計測終了後に別担当へ逐次委任した[独立検証](64-r005-local-kernel-verification.md)を完了した。NumPyで独立列挙したbbox候補と整数SATによりDの590組をIDまで再現し、E/Fと実nativeに渡ったFの座標で変更面の内部重複0を確認した。全239,112個の距離は一軸の窓内全候補探索で一致し、11個の新規悪化は同成分の全出力点との総当たりでも一致した。歪みは辺のGram行列から別式で検算した。中間50反復の向きと固定誤差は保存ログと実装の検査であり、全反復のUVを独立に再計測したわけではない。報告・コード・入力参照・実行結果・検証は[凍結manifest](../experiments/vesuvius/r005/20261112-local-kernel-close/artifact-manifest.json)へ登録する。
