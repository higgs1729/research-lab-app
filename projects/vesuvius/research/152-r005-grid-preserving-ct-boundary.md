# R005: 格子保持は実CTの描画までどこまで保たれるか

## 依頼

2026-11-13。研究150/151で新しい任意モードの二実面の元所有点とXYZを全ビット保持し、異成分競合を0にできた。これをR005の追加技術証拠として採用したが、TIFXYZの保持と下流CT画素の保持は異なる。149の算術では、出力幅に依存するfloat32の画素原点計算に小差が残る。既存第一面のCTと固定領域だけで、下流のどの部分が保たれ、どの部分は変わるかを測る。

対象はR103/104で事前に幾何から選んだ第一面の元面53045/63364周辺、既存64×64・5層のCT比較と保存された約20MiBのCTチャンク。元の未配置TIFXYZと150の格子保持TIFXYZを使う。元ROIと、成分別整数セル移動を下流の画素位置に対応させたROIを先に幾何で固定し、同じ描画条件で比較する。必要なら元の固定領域内で純粋な成分内支持を持つ画素を比較マスクとして定義する。CT結果やモデルスコアを見て場所を探さない。成分を跨ぐ支持が解消されて変わる画素と、元から同成分で支持が保たれる画素を分ける。法線や曲面補間の近傍も元のソースから確認し、2×2だけ同じだから全演算が同じと仮定しない。

使用する4格子点/周辺法線の支持、3D標本位置と深さ順、最終uint8画素を追い、整数平行移動後の一致/不一致を数で報告する。元CTの既存コード/既存観測renderer/計測ツールを借り、別の製品サンプラーは作らない。格子保持だけでは最終画素の完全一致を保証できない場合、差の大きさと発生する条件をそのまま残す。新しい補正アルゴリズムや描画コードの修正へは進まない。元成分2の物理紙面や読みやすさは未確定で、文字発見の主張にはしない。

追加CT/画像/モデル取得、インク推論、ビルド、依存導入、課金なし。実際の標本位置に必要なCTコーナーが保存済みチャンクで揃うかを描画前に確認。足りなければ元の固定範囲で判定できるところまでで止め、データの不足を記録する。固定元ROIの再描画や小さい対応ROIの数回の描画は可。1CPU/AS4GiB/core0/ネットワーク分離、ネイティブ描画合計120秒・集計120秒以内。原票不変、D:読取C:出力、外部送信/公開/PR/応募/追加subagentなし。

成果は本票とexperiments/vesuvius/r005/20261113-grid-preserving-ct01/の入力対応・実行・比較・図（必要なら）・費用・限界・lab候補。作業先.work/r005-grid-preserving-ct01/。次のコード変更や広い探索は主担当の判断へ返す。

モデルgpt-6.1-sol、effort xhigh。元の整数配置と製品描画の画素原点・法線・補間支持を接続する新しい比較設計が必要なため。既知の実描画経路自体は再利用する。

## 結論

[一次・2026-11-13] 固定64×64のうち、成分0と2の純粋な補間支持各1,408画素を整数格子移動で追跡した。四隅の元面IDとXYZ、ネイティブの曲面XYZと符号付き法線は全ビット一致。各成分7,040標本（−2、−1、0、+1、+2 voxel）のXYZ、丸め前float32 CT値、最終uint8も全ビット一致した。元の混合1,280画素の対応位置は、両成分の移動先で補間支持を失い、全5層のTIFFで無効値の0になった。元画像ではこの混合帯の全標本が非ゼロだった。[比較結果](../experiments/vesuvius/r005/20261113-grid-preserving-ct01/compare02/result.json)

## 根拠・詳細

元の選定は研究103/104の凍結領域のまま。描画前に元面53045（成分0）と63364（成分2）の格子点所有者・XYZを追跡し、同じ画素オフセットで対応させた。元のcrop XYWHは `(7428,2378,64,64)`。Xの−2、+59格子セルを実際の描画座標に写すと、各64×64の左上は `(7388,2378)` と `(8608,2378)` になった。Y移動は0。幅変更によるdoubleヘッダー上のX残差は−2.98×10⁻⁸、+8.79×10⁻⁷セルだった。このROIでは `point()` 入口のfloat32化後、純粋支持全画素の格子位置が対応する整数移動と正確に一致した。研究149で調べた他の画素での位相残差は、この局所観測だけでは解消を保証できない。[固定位置・支持](../experiments/vesuvius/r005/20261113-grid-preserving-ct01/plan01/plan.json)

| 観測 | 成分0 | 成分2 |
| --- | ---: | ---: |
| 純粋支持の4点の所有面・XYZ全ビット一致 | 1,408 / 1,408 | 1,408 / 1,408 |
| 補間XYZ・符号付き法線全ビット一致 | 1,408 / 1,408 | 1,408 / 1,408 |
| 5層のXYZ・丸め前CT・最終uint8全ビット一致 | 7,040 / 7,040 | 7,040 / 7,040 |
| CTの8近傍が変わった対応標本 | 0 | 0 |
| 元混合1,280画素の対応先に残った有効画素 | 0 | 0 |

使用したlinear経路は、元コードの `vc_render_tifxyz.cpp` が渡す法線チャンネルなしの頂点格子に対し、`vc_reader/src/cpp/grid/points.hpp` が同じ4点から両線形のXYZを補間し、局所接線の外積から符号付き法線を求める。この経路の法線で隣接セルを読む処理はない。bicubicの頂点微分や別の法線経路は未評価。混合帯は元ROI内の行22–41にあり、元の5層では各層1,280画素が非ゼロで、全層を通じた範囲は9–255。移動先での差は補間支持を失った結果で、同じ物理点を比較した輝度差として扱えない。成分2が正しい紙面か、判読性が改善したか、他の位置・描画条件でも全ビット一致するかは未確定。[生出力・照合手順](../experiments/vesuvius/r005/20261113-grid-preserving-ct01/README.md)

## 取得の経路

研究103の観測rendererを変更・ビルドせず再利用した。元対照の既存TIFF/float/geometryを凍結マニフェストとSHA-256で照合。移動先はメタデータのみのZarrでXYZ・法線を事前計測し、元20,480標本と移動先各7,040標本について、各層の三線形8近傍と±0.001 voxelの保守的な範囲を確認した。必要チャンクは元7、成分0は2、成分2は4。既存20 MiBの保存10チャンクで不足0。描画後に既存Python照合器でCT実バイトから三線形値を確認し、ネイティブ値との最大差は3.82×10⁻⁵輝度単位。丸め前値からの最近接偶数丸めと保存TIFFは全画素一致した。[取得済みキーと描画前確認](../experiments/vesuvius/r005/20261113-grid-preserving-ct01/coverage01/coverage.json)

1CPU、AS 4 GiB、core 0、ネットワーク分離で、ネイティブ2描画0.853秒、幾何観測込み1.816秒、集計累計3.002秒。最大RSSはネイティブ71,491,584バイト、集計121,536,512バイト。追加取得・課金・ビルドは0。[lab登録候補](../experiments/vesuvius/r005/20261113-grid-preserving-ct01/record.json)

## メモ

- R103/104の凍結ROIと既存renderer・CTオブジェクトを使用する。旧新の所有点と補間・法線の実装を確認し、CT値を読む前にROI・比較マスク・必要キーを保存する。
- `plan01`、`geometry01`、`coverage01` の後に `render01` を実行した。最初の集計 `compare01` の後、元対照マニフェストとの自動照合と混合帯の輝度範囲を `compare02` に追加した。同じ生出力を再集計した。

## 主担当の別集計

保存した元所有面と成分から比較マスクを別に再構成し、元の格子四隅・元面ID・XYZを確認した。native geometry.bin、ct-layers.f32と15枚のTIFFを直接読み、純粋支持各1,408画素のXYZ・符号付き法線・5層の計14,080標本座標/float32/uint8が全ビット一致。元混合1,280画素は両移動先でfloat非有限・TIFF0だった。純粋支持の全8CT近傍と±0.001 voxel haloも保存済みキー内だった。主担当の照合は保持と分類の独立確認で、元CT輝度の新たな三線形再実装や再描画は行っていない。[コード](../experiments/vesuvius/r005/20261113-grid-preserving-ct01/lead_check.py)・[結果](../experiments/vesuvius/r005/20261113-grid-preserving-ct01/lead-check.json)。実データ中央層から[比較図](../experiments/vesuvius/r005/20261113-grid-preserving-ct01/ct-preservation-center.png)を作成・目視し、青が無効支持であることを明示した。
