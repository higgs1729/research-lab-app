# R001: w00 の1領域における gen-19 位置対応の独立検証

2026-11-11 JST。w00 の公開ラベル矩形 `[4096:4608, 22528:23040]` では、gen-19 Hecate の予測を両軸に +19 または +20 px ずらして読むと、ずらさない場合より AUC が上がった。保存値からの再集計と、クロップ内の全三角形を調べた別実装の両方で確認した。この領域だけでは、19 と 20 のどちらが適切か、表示・出力のどこを直すべきかは確定しない。

## 保存データの照合

予測値を使わず、supervision、ターゲットクロップ内側、距離 <2 L2 ボクセル、法線の向きを無視した角度 <20°、往復誤差 <8 ソース画素の積で valid を再計算した。保存マスクと完全一致。すべてのシフトで同じ7,597点（陽性5,774、陰性1,823）を使用した。陽性が陰性を上回った割合（同点は半分）を二分探索で求め、順位和を使う元の実装と AUC が一致した。予測の全16,384点についても、保存した Zarr シャードのバイト列から読み直すと3シフトとも保存スコアと一致した。

| 両軸の読み出しシフト | ROC AUC | 固定閾値127.5のTPR | 同FPR | 同バランス精度 |
|---:|---:|---:|---:|---:|
| 0 px | 0.960546 | 56.84%（3,282点） | 0% | 78.42% |
| +19 px | 0.992378 | 62.54%（3,611点） | 0% | 81.27% |
| +20 px | 0.991532 | 62.90%（3,632点） | 0% | 81.45% |

陰性スコアの平均は +19 px で 3.42 から 6.84 に上がったが、この閾値では3条件とも偽陽性は0点だった。+19 px はこの設定の AUC で +20 px を上回り、固定閾値のバランス精度では +20 px が上回った。

## 投影と座標

- 元実装は重心の近い24候補から最短距離の三角形を選ぶ。独立コードは各三角形の外積で面内の重みを求め、面外なら辺への射影も比較した。16,384点全部で順方向599三角形、逆方向1,922三角形を全探索。選ばれた三角形の重心順位は両方向とも最大4位で、24候補の打ち切りによる取りこぼしは見つからなかった。
- 独立コードはソース補間から倍精度で計算した。元の順方向の距離との差は最大0.0014 L2 ボクセル。ターゲット格子位置との差は全点で最大0.0058格子（約0.12予測画素）。往復誤差や法線角にも差が出たが、valid の変化は0点。再投影で読み直した AUC は 0.9605457 / 0.9923780 / 0.9915322。
- TIFF の IFD・Range 本文から、ソース `[202,1124]` とターゲット `[86,55836]` を起点に各 YX クロップを切り出し、各節点の XYZ を保存配列と照合して完全一致した。ソース座標は `(ROI内画素 + ラベル原点 + 0.5)/20 - ソースクロップ原点`。同じ CT の2.4 µm XYZ を4で割って9.6 µmの L2 XYZ と比較し、予測を読む際にのみターゲットクロップ原点を戻す。両メッシュの格子密度は約0.05、予測画像の縦横寸法はターゲットの格子節点数の20倍。これらと [公開データの仕様と来歴](23-r001-data-access.md) の間に明白な不整合は見つからなかった。
- 予測の `20*g+shift` は比較のための座標式。ソースラベルの画素中心式に対応する逆変換は `20*g-0.5` なので、ターゲット画像の位相も別途検査した。データの寸法と再集計だけでは Hecate 生成時の画素原点・位相の契約は決まらない。ソースの画素中心規約と CT ピラミッドの原点は公開資料に従い、CT 本体からの照合は行っていない。

## どこまで言えるか

予測読み出しの共通位相を両軸 −0.5 / 0 / +0.5 px、距離の上限を 0.5 / 1 / 2 / 3 / 4 L2 ボクセルとして、15通りを同じマスク規則で比較した。valid は距離上限に応じ2,452〜11,374点。すべてで +19 px 対 0 px の AUC 差は正（+0.02784〜+0.07076）だった。一方、+19 px と +20 px の AUC の順位は位相と距離上限で逆転した。例として位相0・距離 <0.5 では +20 が約0.00070上、同じ位相・距離 <2 では +19 が約0.00085上だった。

全探索は保存したクロップ内に限定しており、別の巻き・全メッシュの最近傍、他のROI、別セグメント、独立に注釈されたラベル、ソース位相の変更、生成・表示コードの原因は未検証。公開ラベルの来歴にモデルとの依存があり得るため、この AUC で汎化や新しい文字の発見は評価できない。+19 px は [既報の issue #2442](https://github.com/ScrollPrize/villa/issues/2442) に沿った比較条件である。

実行は CPU 約19秒、追加通信0バイト、有料計算の新規調達0 USD（LLM利用・電力は未換算）。入力は `20261111-probe01/` と `20261111-compare01/` の保存データ。出力は [検証コード](../experiments/vesuvius/r001/20261111-verify01/verify_roi.py)、[集計JSON](../experiments/vesuvius/r001/20261111-verify01/result.json)、[全点の幾何とスコア](../experiments/vesuvius/r001/20261111-verify01/geometry.npz)。再実行は `python -B experiments/vesuvius/r001/20261111-verify01/verify_roi.py --out <新しい出力先>`。
