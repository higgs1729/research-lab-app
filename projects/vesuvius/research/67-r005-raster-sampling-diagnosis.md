# R005の旧11セルは描画格子の間に収まっていた

2026-11-12 JST。前回の候補Gで残った11セルは、全頂点が元の描画格子の117行目と118行目の間にあり、自分の2三角形から採用された標本も、重複で拒否された標本も0だった。UVと3D形状をそのままに、既存rasterizerで縦の格子区間数だけ4倍にすると、11セル全ての同一細成分への最近傍距離が20 voxel以下に戻った。これは格子密度に依存する無標本箇所の診断で、実用出力の採用や文字の可読性の改善を示すものではない。[前回のG](65-r005-two-pin-release.md) [事前判断](../experiments/vesuvius/r005/20261112-raster-diagnosis01/decision-record.json)

## 保存済み描画記録による原因の切り分け

対象はDからFで新たに20 voxelを超え、Gでも残った11セル。選び直しはしていない。各セルの元TIFF、細面番号、native UV、所有面、拒否イベント、最近傍点の元面を照合した。

| 保存済み配置 | 11セル中、自面の標本が0のセル | 自面の拒否イベント | セルのUV面積／格子1区画の面積 |
| --- | ---: | ---: | --- |
| D | 0（各1〜2点） | 0 | 約1.175〜1.636 |
| F | 11 | 0 | 約0.129〜0.413 |
| G | 11 | 0 | 約0.156〜0.406 |

元の格子は245×3043、UV間隔はx約19.999603・y約19.964702。Gの11セルの頂点yは117.16814454〜117.95331937。nativeと同じ1/256画素の固定小数点へ丸めても29995〜30196で、整数行117・118に対応する29952・30208の間に収まる。したがってどのセルにも整数行が通らない。局所の重複を取り除いたF/Gでこの帯が圧縮され、元密度では標本を失った。自面が先着の面に負けたという説明には当たらない。[11セルの座標・面・採用点の記録](../experiments/vesuvius/r005/20261112-raster-diagnosis01/diagnosis02/result.json) [丸め後の独立検算](68-r005-raster-diagnosis-verification.md)

![同じGの11セルと描画格子](../experiments/vesuvius/r005/20261112-raster-diagnosis01/figure02/sampling-lattice.png)

図の青線はGのセル境界、黒点は格子の位置。左右で青線は同一。横・縦は元格子単位で、形を見やすくするため縦横比は等しくしていない。図は丸め前の座標で、採用数はnativeの固定小数点描画記録による。

最近傍距離にも限界が見えた。Gのquad92529・92530・92531（元行113・列1371〜1373）の最近傍は、同じ細成分に属するものの、元行112・列1681〜1682の面だった。同じ成分という条件だけでは、元セルの周辺が標本化された証拠にならない。今後は自面の所有数と元面の対応を併記する。

## 配置を変えずに標本密度だけを増やした対照

既存の `UvGridRasterizer::setSrcScale` を利用した。既存のtrace付きobjectを直接リンクする小さなadapterを作り、保存済みGの249,944点・478,224面を同じ順序で渡した。rasterizer本体、共有library、元のflatboiは変更していない。まず元scaleで描画し、所有面・拒否を含むtrace全体と、全float32 XYZが保存済みGに完全一致することを確認してから次の条件へ進んだ。[再現対照](../experiments/vesuvius/r005/20261112-raster-diagnosis01/control-check01/result.json)

次の一回の条件は、横3,042区間を維持し、縦244→976区間とした。高さ245→977、幅3043は同じ。縦scaleを `float32(976 / 4871.38720703125)` として、実間隔はy約4.991175 UV。旧11セルの縦幅が元格子の約0.3区間だったことを踏まえた診断条件で、密度の探索はしていない。[条件・資源の事前記録](../experiments/vesuvius/r005/20261112-raster-diagnosis01/density-decision-record.json)

| 指標 | 元密度G | 縦4倍の診断描画 |
| --- | ---: | ---: |
| 格子の高さ×幅 | 245×3043 | 977×3043 |
| 有効出力点 | 247,527 | 990,247 |
| 描画拒否イベント | 564 | 2,242 |
| 全239,112セル中、同一細成分への最近傍距離20 voxel超 | 277 | 205 |
| 同40 voxel超 | 65 | 52 |
| 旧11セル中、20 voxel超 | 11 | 0 |
| 旧11セル中、自面の標本あり | 0 | 10 |

全体では72セルが20以下へ戻り、新たに20を超えたセルは0だった。旧11セルの距離は21.534〜37.927から1.825〜11.811 voxelへ下がった。10セルは自面から1〜2点採れた。残るquad92532 `(113,1374)` は自面の標本が0のままでも、最近傍までの距離が21.53445→11.81051となった。独立検証では、両密度の最近傍は同じ隣接quad92533 `(113,1375)` の面185066で、描画位置が変わっていた。閾値内へ戻ったことと、自面から点が採れたことは区別する。[全体評価・11セルの個別結果](../experiments/vesuvius/r005/20261112-raster-diagnosis01/density-evaluation01/result.json)

新しい格子の4行おきは元格子と数学上同じUV位置だが、三角形の固定小数点への丸めも変わる。元行と比較して所有面が422箇所で変わり、有効点は3箇所消失・10箇所追加された。同じ所有面のXYZでも最大成分差0.218017578125 voxelがあった。したがって点群を厳密な上位集合とは扱わない。拒否件数の増加も、同密度で幾何が悪化したことを意味しない。UVは同一で、出力点数と描画機会が約4倍になっている。

## 判断、資源、再利用物

Gは元密度の研究用候補として保存したままにし、今回の密度変更は診断に留める。全体の格子を常に4倍にする規則や、最近傍距離だけを良くする固定解放は採用しない。無標本と重複拒否を分ける診断ができたため、次の投入は対象外に残る既知のUV内部重複へ戻す。特に領域129の元メッシュ由来の境界分岐について、既存の非多様体分割手段でチャートを扱えるかを調べる。新しい密度探索、反復増加、追加の固定解放は今回行わない。

再利用物は、nativeの所有面と拒否面を元quadへ追跡する診断、最近傍点の元セルを記録する評価、最適化をやり直さず保存UVで既存rasterizerを呼ぶ小さなadapter、元密度の完全再現を確認して密度条件を分ける実験入力である。元粗点・細点のUVは密度条件間で全て同じであり、新しい配置Hを作ったわけではない。

実行は逐次、CPU1個・1スレッド。adapterビルド19.28秒・最大子RSS約413MB、元密度描画1.90秒・約128MB、縦4倍描画4.38秒・約244MB。各native commandは300秒・AS 4 GiB、Pythonは300秒・RSS 4 GiB監視。最初の診断はNumPyの2次元 `cross` 非対応により1.92秒で失敗し、元script・失敗ログを保持した。2次元の行列式へ直した別scriptで3.32秒で成功した。新規有料計算・GPU・データ取得・依存導入は0。LLMと電力は未金額換算。共有ホストのO0実行であり、上記を性能改善として比較しない。

実験を再利用する際は、`20261112-raster-diagnosis01/prepare_density.py` の入力形式、`native_density.py` に保存したcompile/link/保護hash、`raster_density.cpp` の既存API呼出しを参照する。WSLでの実行例は `python3 native_density.py control --out <新規出力先>`。出力先は毎回分ける。全体の `points.bin` は高さ・幅のuint64に続くfloat32 XYZで、配布用tifxyz metadataではない。

主計測終了後、Sol / highを選び直して[独立検証](68-r005-raster-diagnosis-verification.md)を逐次実施した。別担当は選択22面の固定小数点top-left判定を独立に再現し、D/F/Gと縦4倍の所有・拒否座標を照合した。元密度の全traceとfloat32 XYZの完全一致、全239,112セルの距離、旧11セルの最近傍の元面も確認した。新たなbuild・native描画・solverは検証で行っていない。[凍結manifest](../experiments/vesuvius/r005/20261112-raster-diagnosis-close/artifact-manifest.json)に入力・コード・結果・失敗記録・図・検証をまとめる。
