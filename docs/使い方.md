# 使い方

Research Lab を起動して、画面で研究を記録・管理するための説明書です。仕組みの説明は [アーキテクチャ.md](アーキテクチャ.md) にあります。

## 必要なもの

- Python 3.11 以上(標準ライブラリだけで動きます。`pip install` は要りません)
- ブラウザ(Edge・Chrome・Firefox など)

インターネット接続、外部サービスのアカウント、API キー、GPU も要りません。

## 起動する

`app.py` があるフォルダでターミナルを開き、次のどれかを実行します。

| コマンド | 開くプロジェクト | 向いている用途 |
|---|---|---|
| `python app.py --research` | `projects/vesuvius/`(実際の研究記録 359 件) | 実運用でどう使ったかを見る |
| `python app.py --demo` | `projects/demo/`(合成の教材データ) | 操作を一通り試す |
| `python app.py` | `projects/default/`(空。無ければ作る) | 自分の研究を一から記録する |
| `python app.py --root "./my-research"` | 指定したフォルダ | 別のプロジェクトを開く |

起動すると既定のブラウザで `http://127.0.0.1:8780` が開きます。8780 番を別のアプリが使っていれば、空いているポートに自動で切り替わり、ターミナルにその URL が出ます。終了はターミナルで **Ctrl+C** です(ブラウザを閉じてもサーバーは止まりません)。データは止めても残ります。

ほかのオプション:

- `--no-browser`:ブラウザを自動で開かない(表示された URL を手で開く)
- `--port 0`:最初から空いているポートを使う
- `--research` は `--demo`・`--root` と同時には使えません

`--research` の記録は実データです。操作するとその DB に書き込まれます。元に戻したいときは、提出時のフォルダから `projects/vesuvius/` をコピーし直してください。試すだけなら `--demo` を使ってください。

## 画面の見方

上から順に、次の 3 つがあります。

1. **状態の線**:「準備中 ― 稼働中 ― 一時停止 ― 判断待ち」のうち、今の状態が点灯します。その下に主担当の名前と、判断待ちならその理由が出ます。
2. **タブ**:研究記録・監査提案・起こす判定・履歴。監査提案のタブには、判断を待っている提案の数が出ます(1 件以上なら色が付きます)。
3. **右の欄**:主担当の登録と、判断待ちにする操作。

別の画面や CLI から操作したときは、右上の「最新に更新」を押すと反映されます(画面は自動では更新しません)。

### 主担当を登録する(右の欄)

研究を進める担当を 1 つだけ登録できます。「主担当の名前」と「環境」(PC の名前など。任意)を入れて「開始する」を押すと、状態が稼働中になります。

- 稼働中に別の名前で「開始する」を押すと拒否されます。主担当を替えるときは、先に「一時停止」してから開始します。
- 本人の判断が要るときは「私の判断を待つ理由」を書いて「判断待ちにする」を押します。理由は再起動しても残ります。

### 研究記録

何を試し、何が分かったかを、根拠ファイルと一緒に残すタブです。

**記録を追加する**:「記録を追加」を押すと入力欄が開きます。

- 種類:実験・検証・判断・資源・費用・監査
- どこまで確かか:仮説(未検証)/観測した/別の担当が検証した
- 要約(必須)、作業時間・本人の対応時間・費用・計算資源(任意)
- 根拠ファイル(1 件以上必須):プロジェクトのフォルダの中にあるファイルから選びます

根拠の無い記録、フォルダの外のファイルは登録できません。保存すると、根拠ごとに登録時の SHA-256(ファイルの指紋)が記録されます。先にファイルをプロジェクトのフォルダへ置き、「最新に更新」を押すと候補に出ます。

**記録を探す**:一覧の上で絞り込めます。

- 検索欄:要約・問い・条件などの文字で絞る
- 種類の選択
- 「画像つきだけ」:根拠に画像がある記録だけにする

右端に「表示数 / 総数 件」が出ます。

**根拠を照合する**:各記録の下に根拠ファイルが並びます。

- 画像(PNG・JPEG・GIF・WebP)は縮小して表示します。押すと拡大し、照合の結果も出ます。
- そのほかのファイルは「照合」を押すと中身(先頭 64 KiB まで)と照合の結果が出ます。
- 根拠が 5 件以上あるときは、最初の 4 件だけを出し、残りは「ほかの根拠 N 件」に畳みます。

照合では、登録時の指紋と今のファイルの指紋を比べます。同じなら「登録したときから中身は変わっていません。」、違えば赤で両方の指紋を出します。

**「同梱していない」と出る根拠について**:`--research` の実研究記録では、根拠ファイル 2534 個のうち 1898 個(12.0 MB)だけを提出物に入れています。大きな実験結果(CT の画像の束やログなど)まで入れると提出物が数 GB になるためです。入れなかった根拠も、記録とパス・指紋はすべて残っており、画面では「同梱していない」と表示されます。どれを入れるかは `tools/import_research.py` が決めています(1 ファイル 200 KB 以下を、Markdown → 画像 → JSON → テキスト → コードの順に、合計 12 MB まで)。

また、入れた根拠のうち 2 個は、元の研究で登録したあとに中身が書き換わっていたため、照合すると赤で「変わっている」と出ます。これは不具合ではなく、照合の仕組みが働いている例です。

### 監査提案

進め方を点検する監査役が、改善を提案するタブです。

1. 「提案を書く」で、気づいた問題・変えること・期待する効果・かかる負担・根拠ファイルを入れて「提案を登録」。
2. 「判断を待っている提案」に並びます。まったく同じ内容(根拠の指紋まで同じ)の提案は「同じ内容と根拠の提案がもうある」と出て、二重には登録されません。
3. 主担当が受け取ったら「主担当が受け取ったことを記録」を押します(稼働中で、まだ今の主担当が受け取っていないときに出ます)。外部へ送る機能ではありません。
4. 理由を書いて「採用する」「保留する」「不採用にする」のどれかを押します。理由が空だと保存できません。
5. 判断した提案は「判断済み」に移ります。採用したものには「採用してどうなったか」の欄が出るので、結果を書いて「結果を保存」します。判断は理由を書けば見直せます。

### 起こす判定

主担当が手を止めているときに「今起こしてよいか」を判定するタブです。主担当の様子を見て、2 つのチェック(「作業を終えて待っている」「私の入力や承認を待っている」)を付け、「今起こすか判定する」を押します。

次の条件を全部満たすときだけ「起こす」と判定され、その 30 分枠に予約が入ります。

- 状態が稼働中
- 画面に出ている主担当が今の登録と同じ
- 作業を終えて待っていて、入力や承認は待っていない
- 同じ 30 分枠でまだ予約していない

判定の結果と理由(満たさなかった条件)が表示されます。**判定は予約までで、AI を起動したり外部へ送ったりはしません。** 30 分枠は時計の区切り(UTC の 0 分・30 分始まり)で、前回から 30 分空ける方式ではありません。

### 履歴

状態の変更・記録・提案・受け取り・採否・結果・起こす判定を、新しい順に並べます。項目を開くと、そのときの中身が見られます。

### 通知とエラー

操作の成功は緑、エラーは赤の通知で画面の上に出ます。エラーには、何が足りないか(例:「根拠（evidence）にはプロジェクト内のファイルを1件以上指定してください。」)が書かれています。

## コマンドラインから使う

画面と同じ中核を CLI からも使えます。`--root` はサブコマンドの前に書きます。

```text
python tools/lab.py --root projects/demo status
python tools/lab.py --root projects/demo records
python tools/lab.py --root projects/demo inbox
python tools/lab.py --root projects/demo activate --thread lead-01 --host local
python tools/lab.py --root projects/demo hold --reason "研究対象の変更を相談する"
python tools/lab.py --root projects/demo pause
python tools/lab.py --root projects/demo record --file record.json
python tools/lab.py --root projects/demo propose --file proposal.json
python tools/lab.py --root projects/demo decide 提案ID accept --reason "理由"
python tools/lab.py --root projects/demo outcome 提案ID --result "結果"
python tools/heartbeat.py --root projects/demo --snapshot snapshot.json
```

記録の JSON の例:

```json
{"kind":"experiment","summary":"最小例の反転数を比較","claim_status":"observed","evidence":["evidence/02-measurements.json"]}
```

提案の JSON の例:

```json
{"problem":"比較条件が不足","change":"交差判定を追加","benefit":"採用判断を改善","cost":"小さなCPU試験","evidence":["evidence/03-verification.txt"]}
```

起こす判定の観測の例(`observed_at` は観測した時刻の Unix 秒):

```json
{"thread_id":"flattening-lead","host_id":"local","observed_at":0,"status":"idle","needs_input":false}
```

`--thread` と `thread_id` は、元の研究体制との互換のために残した名前です。ここでは主担当の名前(任意の文字列)を意味します。

## 自動テスト

```text
python -m unittest
python smoke_check.py
```

`python -m unittest` は 36 本のテストを流します(中核・起こす判定・HTTP API・デモ・同梱した研究記録)。`smoke_check.py` は `app.py` を別のプロセスで起動し、HTTP で主な操作をしてから止め、結果を `verification-output/smoke.json` に書きます。どちらも `projects/` の中のデータには触りません(テスト用のフォルダは `runtime/` の下に作って消します)。

## 困ったとき

| 症状 | 対処 |
|---|---|
| `python` が見つからない | Python 3.11 以上を入れる。Windows では `py app.py --demo` でも起動できます |
| `[WinError 10013]` などで起動できない | `--port 0` を付けて空いているポートで起動する |
| ブラウザが開かない | ターミナルに出た `http://127.0.0.1:…` を手で開く |
| 「起動時に表示された 127.0.0.1 のURLで開いてください」 | `localhost` ではなく `127.0.0.1` の URL で開く |
| 「操作元を確認できません。画面を再読み込みしてください」 | サーバーを起動し直すと操作用の鍵が変わるため。ページを再読み込みする |
| 置いたファイルが根拠の候補に出ない | 「最新に更新」を押す。`runtime/`、`.` で始まるファイル・フォルダ、リンクは候補に出ません |
| 根拠に「同梱していない」と出る | 上の「同梱していない」の説明のとおりで、提出物の容量を抑えるためです |
| `--research` で「研究記録が見つかりません」 | `projects/vesuvius/runtime/lab.sqlite3` が欠けています。提出時のフォルダからコピーし直す |
